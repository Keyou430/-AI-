# 管理员停用后的本地 API 清理

本次仅区分管理员操作与员工操作，设备仍共用一份加密 API 配置，不实施账号业务数据隔离。

| 操作 | 本地 API 配置 |
| --- | --- |
| 员工主动退出、同设备换号、重新登录 | 保留 |
| 会话自然到期、网络故障、管理员重置密码、直接删除账号 | 保留（若此前已有停用指令，仍处理该指令） |
| 管理员停用普通账号 | 员工客户端取得可信停用结果后清除，管理员设备配置保留 |
| 停用后重新启用 | 不恢复被清除的旧配置 |

清除范围为本设备的文字模型、内容提取和图片生成配置及配置临时文件；历史、知识库和素材保留。退出时原有的前端临时密钥清空行为保留，加密配置文件不删除。

普通账号从启用变为停用时，授权数据库的 api_reset_version 增加。服务为旧令牌保留停用原因直到原有效期届满；重新启用不能恢复旧令牌权限。客户端的 provider-reset-versions.json 只保存按授权来源及不可变账号 ID 区分的处理进度，不保存密钥。已在本机登录过的账号，即使离线错过停用、之后重新启用，也在下次成功登录、业务开放前核对版本并补清理。首次登录一个未知账号只建立版本基线，避免同设备换号误删已有配置；收到已验证密码的明确停用结果时可以清理。

清理前核对原登录会话，已退出或换号后的迟到响应不执行清理。清理或记录失败时撤销员工会话并显示 API_RESET_FAILED，不确认清理完成，后续登录可重试。停用其他管理员不会触发 API 清理。

远程使用须同时更新授权服务和员工客户端，建议先更新服务。旧服务仅返回通用登录失效时，客户端不能推断为停用并清理。离线或关闭的客户端无法即时删除文件，须在收到停用响应或后续登录核对版本时执行。2026-11-05 已部署远程授权服务并通过服务器隔离验收及生产健康检查；随后已生成配套 1.0.26 员工安装包并通过正式包 9 项清理验收，未自动安装到员工设备。服务部署证据见 release/auth-service-api-reset-20261105/remote-deployment-result.json；安装包验收见 release/universal-package-acceptance-1.0.26.json。

验证：tests/providerReset.test.ts 覆盖操作来源、离线补处理、清理失败、迟到响应、版本迁移等；scripts/providerResetSmoke.cjs 在临时目录使用真实 Electron、safeStorage、IPC、员工入口和 WASM SQLite 验证（Node 回归覆盖原生 SQLite），不调用模型供应商。
