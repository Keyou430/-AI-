# 通用版账号服务部署

更新日期：2026-10-22；当前客户端版本：1.0.4，本次未更新鉴权服务部署。

## 职责与地址

正式服务为 https://114.132.186.95，Ubuntu 上由 Caddy 提供 HTTPS，后台仅监听 127.0.0.1:3080。systemd 单元为 video-remix-auth.service，开机启动。

服务器只处理账号登录、权限与状态校验、账号创建、停用、密码重置、退出和审计。开放的业务路径为 /health 以及 /v1/login、/v1/me、/v1/logout、/v1/users、/v1/users/create、/v1/users/status、/v1/users/password；原 /v1/providers 和 /v1/business/* 返回 404。

通用版在本机保存知识库、关键词、业务简介和加密接口配置，由本机直接请求模型及视频解析供应商。服务器不存储或转发 API Key、提示词或生成内容。新设备空白；同设备账号共享本机资料。员工可自行保存本机接口，账号管理仅管理员可用。

## 运行目录与备份

- 代码：/opt/video-remix-auth/dist-server，仅包含账号服务及账号数据库、日志依赖。
- 账号数据库：/var/lib/video-remix-auth/video-remix-history.sqlite。沿用原 SQLite 文件以保留已有账号，服务使用 sql.js，不支持多个实例同时写同一数据库。
- 日志：/var/lib/video-remix-auth/logs，记录操作者、目标、时间和结果，不记录密码、令牌及请求正文。
- 初始密码文件：/etc/video-remix-auth/admin-password，仅用于空数据库初始化，修改该文件不会重置既有账号密码。
- 本次更新备份：/var/backups/video-remix-auth/universal-20261022T064308Z，包含旧代码、依赖清单及更新前完整数据；旧供应商配置经检查无密钥，已移入该目录，不再放在运行数据目录。

运行数据目录为 remixauth 所有、0700。备份须限制访问并定期保留到其他存储；客户端资料需在各设备自行备份。服务重启会撤销全部内存会话，用户重新登录。

## 构建和更新

通用安装包：

~~~powershell
npm run dist:win
~~~

默认连接正式地址；如需其他环境，通过 REMIX_AUTH_URL 设置有效 HTTPS 根地址。输出 release/video-remix-universal-setup-1.0.4.exe。管理员和员工使用同一份安装包，角色由账号服务决定，不依赖客户端本机管理员标记。

授权服务编译：

~~~powershell
npm run build:auth
~~~

更新时先停止服务并备份代码与 /var/lib/video-remix-auth，再用新的 dist-server 及依赖清单替换。不要把旧目录直接叠加到新目录，避免残留已退役的业务代理模块。依赖无变化可复用 node_modules；需要重新安装时执行：

~~~bash
sudo npm ci --prefix /opt/video-remix-auth --omit=dev --omit=optional --ignore-scripts --no-audit --no-fund
sudo systemctl restart video-remix-auth
sudo systemctl is-active video-remix-auth
curl --fail http://127.0.0.1:3080/health
~~~

部署后确认 HTTPS 健康、登录、权限、停用及重置密码会话撤销；原供应商端点应返回 404，运行目录不得新增供应商配置文件。

## 停权与边界

客户端每次操作鉴权，空闲时每 30 秒检查，任务执行时每秒检查。检测到停用、密码重置、会话到期或授权服务不可达时取消任务并锁定；生效时间还包含网络检查耗时。退出立即取消本机任务，重新启用账号不会恢复旧会话。

业务为本机直连，服务器无法收回已导出内容、已复制的 Key，亦不能保证阻止修改程序后绕过本机限制的行为。API Key 采用 Windows 系统安全存储保护静态数据，仍需在供应商侧管理额度与撤销。

Caddy 覆盖 X-Real-IP，后台只信任回环代理，按来源和区分大小写的账号限流；不要公开 3080。保持证书续期所需的 Caddy 与网络配置正常。请求仍受原代理大小限制，账号接口在后台限制为 16 KB。

## 验收

类型检查与 59 项自动化测试通过；本机隔离桌面流程验证日志、权限、知识库与创作流程。通用包联网持久化脚本在四个独立进程中验证首次填写、修改、重启与新设备空白，Windows 加密可用，并验证前端修改 GET、查询参数鉴权及字段路径后跨重启继续生效；供应商请求使用本机配置的验收响应，服务器收到的请求仅为账号相关接口。

证据文件位于 release/universal-persistence-acceptance.json；ASAR 与完整性开关核验位于 release/universal-package-acceptance.json；历史 1.0.3 双客户端角色及停权验收位于 release/universal-auth-acceptance.json。尚未完成代码签名、两台实体员工设备安装卸载及真实商业供应商联调。历史 1.0.1 / 1.0.2 证据记录的是当时架构，不代表当前仍启用服务端业务代理。
