## 职责与地址

正式服务为 https://114.132.186.95，Ubuntu 上由 Caddy 提供 HTTPS，后台仅监听 127.0.0.1:3080。systemd 单元为 video-remix-auth.service，开机启动。

服务器只处理账号登录、权限与状态校验、账号创建、删除、停用、密码重置、退出和审计。开放的业务路径为 /health 以及 /v1/login、/v1/me、/v1/logout、/v1/users、/v1/users/create、/v1/users/status、/v1/users/password、/v1/users/delete；原 /v1/providers 和 /v1/business/* 返回 404。

通用版在本机保存知识库、关键词、业务简介和加密接口配置，由本机直接请求模型及视频解析供应商。服务器不存储或转发 API Key、提示词或生成内容。新设备空白；同设备账号共享本机资料。员工可自行保存本机接口，账号管理仅管理员可用。

## 构建和更新

通用安装包：

~~~powershell
npm run dist:win
~~~

默认连接正式地址；如需其他环境，通过 REMIX_AUTH_URL 设置有效 HTTPS 根地址。当前输出 release/video-remix-universal-setup-1.0.26.exe。管理员和员工使用同一份安装包，角色由账号服务决定，不依赖客户端本机管理员标记。

授权服务编译：

~~~powershell
npm run build:auth
~~~

更新时先停止服务并备份代码与 /var/lib/video-remix-auth，再用新的 dist-server 及依赖清单替换。不要把旧目录直接叠加到新目录，避免残留已退役的业务代理模块。依赖无变化可复用 node_modules；需要重新安装时执行：

~~~bash
sudo npm ci --prefix /opt/video-remix-auth --omit=dev --omit=optional --ignore-scripts --no-audit --no-fund
sudo systemctl restart video-remix-auth
sudo systemctl is-active video-remix-auth
curl --fail http://127.0.0.1:3080/health
~~~

部署后确认 HTTPS 健康、登录、权限、停用及重置密码会话撤销；原供应商端点应返回 404，运行目录不得新增供应商配置文件。

## 停权与边界

客户端每次操作鉴权，空闲时每 30 秒检查，任务执行时每秒检查。检测到停用、密码重置或会话到期时取消任务并退出登录；生效时间还包含网络检查耗时。授权服务暂时不可达、超时或响应异常时保留本地会话，但拒绝当前需要授权的操作并中断在途任务，提示具体原因；后台继续校验，连接恢复且服务端会话仍有效时无需重新登录，可重试操作。失败原因以 auth.verification-failed 写入客户端脱敏日志，保留原始错误码及底层错误类型。退出立即取消本机任务，重新启用账号不会恢复旧会话。

业务为本机直连，服务器无法收回已导出内容、已复制的 Key，亦不能保证阻止修改程序后绕过本机限制的行为。API Key 采用 Windows 系统安全存储保护静态数据，仍需在供应商侧管理额度与撤销。

Caddy 覆盖 X-Real-IP，后台只信任回环代理，按来源和区分大小写的账号限流；不要公开 3080。保持证书续期所需的 Caddy 与网络配置正常。请求仍受原代理大小限制，账号接口在后台限制为 16 KB。
