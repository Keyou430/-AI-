# 服务器授权服务部署步骤

适用版本：视频二创 AI 助手 1.0.27
整理日期：2026年11月5日
适用人员：服务器运维、实施人员、平台管理员

本文用于部署集中账号授权服务并接入 Windows 客户端，顺序：准备环境 → 制作部署包 → 首次部署 → 配置 HTTPS → 验收 → 安装绑定客户端 → 备份恢复。以下为待执行步骤，未在生产环境实施。

### 1.2 架构与成功标准

员工客户端通过 HTTPS 访问授权服务，Caddy 或 Nginx 反代到 127.0.0.1:3080。服务只负责登录、角色、账号管理、会话撤销和日志，不代理二创、提取、生图，不保存员工 Key、知识库或生成内容；客户端直连供应商，本机保存历史、背景、关键词、知识库、素材和加密接口配置。管理员与成员使用同一安装包，权限由服务端角色决定。

成功标准：开机自启；3080 只监听回环；证书正常；安装探测接口返回预期结果；空库能初始化管理员；管理员能管账号、成员不能；客户端完成绑定登录；备份有恢复验证记录。

## 3 准备服务器部署包

在干净源码目录编译，避免混入旧 dist-server；不要打包应用数据、密码或供应商密钥。在 Windows PowerShell 中执行，任一步失败先处理：

```powershell
npm ci
if ($LASTEXITCODE -ne 0) { throw '依赖安装失败，停止编译' }
npm run build:auth
if ($LASTEXITCODE -ne 0) { throw '授权服务编译失败，停止打包' }
Test-Path '.\dist-server\server\main.js'
tar -czf '.\auth-service-1.0.27.tar.gz' dist-server deploy package.json package-lock.json
if ($LASTEXITCODE -ne 0) { throw '部署包生成失败' }
Get-FileHash '.\auth-service-1.0.27.tar.gz' -Algorithm SHA256
```

记录哈希并上传。以下以 /tmp/auth-service-1.0.27.tar.gz 为例，核对服务器与 Windows 哈希一致后解压：

```bash
sha256sum /tmp/auth-service-1.0.27.tar.gz
mkdir -p /tmp/video-remix-auth-1.0.27
tar -xzf /tmp/auth-service-1.0.27.tar.gz -C /tmp/video-remix-auth-1.0.27
test -f /tmp/video-remix-auth-1.0.27/dist-server/server/main.js
```

重建客户端用 npm run dist:win；REMIX_AUTH_URL 只影响旧固定地址版升级，仅部署服务无需构建前端。

## 4 首次部署账号服务

本节只用于首次部署；已有账号库按第 9 节升级，不要覆盖数据目录或重新初始化管理员。

### 4.1 创建账户与目录

```bash
getent passwd remixauth || sudo useradd --system --home-dir /var/lib/video-remix-auth --no-create-home --shell /usr/sbin/nologin remixauth
sudo install -d -o root -g root -m 0755 /opt/video-remix-auth
sudo install -d -o remixauth -g remixauth -m 0700 /var/lib/video-remix-auth
sudo install -d -o root -g remixauth -m 0750 /etc/video-remix-auth
sudo install -d -o root -g root -m 0700 /var/backups/video-remix-auth
sudo cp -a /tmp/video-remix-auth-1.0.27/dist-server /opt/video-remix-auth/
sudo install -o root -g root -m 0644 /tmp/video-remix-auth-1.0.27/package.json /opt/video-remix-auth/package.json
sudo install -o root -g root -m 0644 /tmp/video-remix-auth-1.0.27/package-lock.json /opt/video-remix-auth/package-lock.json
sudo npm ci --prefix /opt/video-remix-auth --omit=dev --omit=optional --ignore-scripts --no-audit --no-fund
```

任一命令失败先处理。仅安装生产依赖，跳过 Electron 脚本和可选原生依赖，使用 sql.js；程序目录由 root 管理，服务账户只写数据目录。

### 4.2 设置初始管理员密码

交互输入 8 至 128 位密码，不写入命令、文档或截图。下列命令只在长度合格时写入：

```bash
sudo -v
read -r -s -p '设置初始管理员密码: ' initial_password
printf '\n'
password_length=$(printf '%s' "$initial_password" | wc -m)
if [ "$password_length" -ge 8 ] && [ "$password_length" -le 128 ]; then
  printf '%s' "$initial_password" | sudo tee /etc/video-remix-auth/admin-password >/dev/null
  sudo chown root:remixauth /etc/video-remix-auth/admin-password
  sudo chmod 0640 /etc/video-remix-auth/admin-password
else
  printf '密码长度不合格，未写入，请重新执行本步\n' >&2
fi
unset initial_password password_length
sudo -u remixauth test -r /etc/video-remix-auth/admin-password
```

仅空库创建内置 admin；已有数据库时修改密码文件不会重置密码，应在客户端“账号管理”重置。

### 4.3 配置并启动 systemd

```bash
sudo install -o root -g root -m 0644 /tmp/video-remix-auth-1.0.27/deploy/video-remix-auth.service /etc/systemd/system/video-remix-auth.service
sudo systemctl daemon-reload
sudo systemctl enable --now video-remix-auth.service
sudo systemctl is-active video-remix-auth.service
sudo journalctl -u video-remix-auth.service -n 60 --no-pager
curl --fail --max-time 10 http://127.0.0.1:3080/health
```

预期服务 active，/health 返回 {"success":true}。AUTH_PORT 默认 3080，AUTH_DATA_DIR 默认 ./auth-data，正式部署用 /var/lib/video-remix-auth；AUTH_ADMIN_PASSWORD_FILE 指向前述文件，AUTH_ADMIN_NAME 仅空库初始化用。模板已设 remixauth、UMask=0077、ProtectSystem=strict 和 ReadWritePaths；改数据目录须同步改 AUTH_DATA_DIR、权限和 ReadWritePaths。

## 5 配置 HTTPS 入口

### 5.1 Caddy 路线

在现有 /etc/caddy/Caddyfile 中合并站点，保留其他站点和全局设置；替换 auth.example.com 并完成证书配置与续期：

```text
https://auth.example.com {
    request_body {
        max_size 1MB
    }
    reverse_proxy 127.0.0.1:3080 {
        header_up X-Real-IP {remote_host}
        flush_interval -1
    }
}
```

```bash
sudo caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
sudo systemctl reload caddy
sudo systemctl is-active caddy
sudo journalctl -u caddy -n 60 --no-pager
```

deploy/Caddyfile.auth.example 是纯 IP 模板（固定 IP、default_sni、shortlived 证书），不能原样用于其他地址。首次安装要求系统信任证书，不得关闭校验。

### 5.2 已采用 Nginx 的环境

采用 deploy/nginx-auth.conf.example，替换域名和证书路径，limit_req_zone 放在 http 上下文；代理覆盖 X-Real-IP 并转发 127.0.0.1:3080，nginx -t 后重载。证书续期按环境配置，勿与 Caddy 争用端口。

## 6 部署验收

### 6.1 无账号接口与网络检查

替换示例地址，在服务器和至少一台员工网络电脑检查公网 HTTPS，不添加 curl -k：

```bash
sudo systemctl is-active video-remix-auth.service
sudo ss -lntp | grep ':3080'
curl --fail --max-time 10 http://127.0.0.1:3080/health
curl -i --max-time 10 https://auth.example.com/health
curl -i --max-time 10 https://auth.example.com/v1/me
curl -i --max-time 10 https://auth.example.com/v1/providers
curl -i --max-time 10 https://auth.example.com/v1/business/probe
```

| 检查 | 预期结果 |
| --- | --- |
| 监听 | 127.0.0.1:3080，不能是 0.0.0.0:3080 |
| GET /health | HTTP 200；success 为 true |
| 未登录 GET /v1/me | HTTP 401；success 为 false；errorCode 为 AUTH_REQUIRED |
| 退役业务路径 | /v1/providers 与 /v1/business/probe 返回 404 |
| 公网 HTTPS | 无证书错误；探测路径直接返回 JSON，无重定向 |

健康接口只证明存活，不代替数据库和权限验收。账号接口为 POST /v1/login、/v1/logout、GET /v1/users 及 POST /v1/users/create、/status、/password、/delete；管理员在客户端维护账号。

### 6.2 用隔离账号验收权限

用可清理的临时成员和测试设备，避免停用真实账号。管理员登录客户端后按表验收并登记：

| 场景 | 合格标准 |
| --- | --- |
| 管理员 | admin 能登录并显示“账号管理”，可创建临时成员和管理员 |
| 成员权限 | 无账号管理菜单；直接调用账号管理接口返回 403 |
| 内置保护 | 不能停用或删除内置 admin 及当前登录账号 |
| 停用／启用 | 停用后原会话失效并清理三类 API 配置；启用后可登录，旧 Key 不恢复，历史和素材保留 |
| 重置／删除 | 重置后旧会话失效、API 配置保留；删除不可撤销，本地历史保留 |

停用清理需配套服务端协议和新客户端；配置由当前 Windows 用户共享，服务器无法立即擦除离线客户端，也不能撤销供应商 Key。会话默认 12 小时，令牌仅在服务进程内存，重启失效；不要多进程负载均衡或多副本共写库。

## 7 安装并绑定 1.0.27 客户端

### 7.1 首次安装

1. 核对 EXE 与 SHA256，启动向导并选择安装位置。
2. 在“绑定授权服务器”填写 HTTPS 根地址，如 https://auth.example.com，不填写 /health、/v1、用户名、密码、查询参数或片段。
3. 点击下一步；安装器探测 /health 和未登录 /v1/me，每次超时 8 秒，错误、重定向或接口不符会阻止绑定；确认地址不可修改后完成安装。
4. 启动软件，用 admin 或分配的成员账号登录；客户端不初始化管理员。

绑定保存为当前 Windows 用户应用数据目录的 auth-server-binding.json；不能跳过，软件无修改入口；绑定缺失或损坏时拒绝启动并提示重装。

### 7.2 升级与更换地址

| 情况 | 1.0.27 行为 |
| --- | --- |
| 有效绑定后覆盖安装 | 保留绑定和 API 配置，不重复填地址 |
| 旧固定地址版直接升级 | 沿用构建时的兼容地址，本次预设为 https://114.132.186.95 |
| 已绑定而服务器离线 | 保留绑定，不因离线重新绑定 |
| 主动卸载 1.0.27 | 清除绑定、加密 API 配置、进度及临时文件，保留数据库与素材 |
| 卸载后重新安装 | 可重新填地址，三类 API 配置需要重填 |

升级内部卸载保留配置，不要为普通升级主动卸载。确需换服务器，先备份资料并准备 Key，再用 1.0.27 卸载程序重装。

## 8 日常运维与备份恢复

### 8.1 维护窗口内备份

sql.js 在进程内管理数据库，为获取一致副本，停止服务后备份。日常检查用 systemctl status、journalctl -u video-remix-auth.service -n 100 和 /health；日志在 /var/lib/video-remix-auth/logs，客户端通过“设置 → 系统设置 → 打开运行日志”取证。以下适用于前文目录及 Caddy 路线：

```bash
backup_dir="/var/backups/video-remix-auth/manual-$(date -u +%Y%m%dT%H%M%SZ)"
sudo install -d -o root -g root -m 0700 "$backup_dir"
sudo systemctl stop video-remix-auth.service
sudo tar -czpf "$backup_dir/backup.tar.gz" -C / \
  opt/video-remix-auth var/lib/video-remix-auth etc/video-remix-auth \
  etc/systemd/system/video-remix-auth.service etc/caddy/Caddyfile
sudo tar -tzf "$backup_dir/backup.tar.gz" >/dev/null
sudo sha256sum "$backup_dir/backup.tar.gz"
sudo systemctl start video-remix-auth.service
sudo systemctl is-active video-remix-auth.service
```

tar 失败先排查，确认备份无效则不升级。Nginx 环境替换实际代理配置，证书和代理状态目录另行备份。备份含密码文件，仅 root 可访问，另留受控异地副本并记录哈希；服务器备份不含员工电脑中的历史、知识库和素材，需另行备份。

### 8.2 恢复原则

先在隔离目录或备用服务器解压检查。停止服务并保存现场，成套恢复匹配的代码、依赖、账号数据、配置和服务单元；不要只覆盖数据库或让两个实例同时访问同一目录。恢复后 daemon-reload、启动服务并做第 6 节验收，恢复过代理则先校验再重载；所有客户端重新登录，核对账号停用状态和密码。备份须在隔离环境实际恢复并登录验证一次。

## 9 升级与回滚

1. 记录入口、代理配置、账号数量与状态；核对新包哈希并沿用原数据目录。
2. 按第 8 节停止服务，备份代码、依赖和完整数据，检查成功后继续。
3. 暂存目录准备新程序及生产依赖并确认入口；保留旧程序目录，不叠加到旧 dist-server；沿用账号目录和密码文件。
4. 启动后验收接口、权限和账号保留情况，用隔离成员验证停用协议；无必要不改代理、地址或证书，登记版本、哈希、时间与入口。
5. 失败时停止新服务，保存日志和数据副本，恢复升级前的代码、依赖与数据，复验后通知用户重新登录。

保持同一 HTTPS 地址可避免用户重新绑定；确需换地址，按第 7 节迁移并重填 Key。

## 10 常见故障处理

| 现象 | 优先检查与处理 |
| --- | --- |
| 服务启动失败 | journal、node 路径、依赖、密码文件可读性与长度、数据目录权限 |
| 本机健康正常、公网失败 | 代理状态、防火墙、域名解析、证书匹配与有效期 |
| 安装验证失败 | HTTPS 根地址、探测接口的 JSON 和重定向、员工网络；不要关闭证书校验 |
| 升级仍连接原地址或重启要登录 | 原地址是保留绑定的预期行为；会话在内存，重新登录，不要删库 |
| 停用后 Key 消失 | 停用清理行为；启用后由成员重填 |
| 误开多实例或 API_RESET_FAILED | 恢复单实例并保留现场；检查客户端数据目录权限和清理错误，不删除业务库 |

客户端新任务须校验授权，空闲约每 30 秒、运行任务约每 15 秒校验，窗口获得焦点也校验；只读身份查询失败会重试一次，已提交任务按最近成功授权起最多 60 秒宽限。明确停用或会话失效会取消本机任务，但取消不代表供应商任务取消或退款。
