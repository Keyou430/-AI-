# 桌面端技术栈选型评估报告 (V1.2 修订版 - 含账号管理与权限管控方案)

针对“视频二创AI助手”桌面端应用的需求，综合考虑开发效率、系统性能、跨平台兼容性、团队账号可用性管控以及 AI 能力的接入，推荐以下技术栈方案。

## 1. 整体架构方案推荐
**推荐架构：Electron + React 18 + Node.js (本地主进程服务) + SQLite + 轻量云端鉴权同步（可选扩展）**

*   **理由**：Electron 生态极其成熟，前端开发人员可快速上手，且对本地文件系统（知识库解析）、本地数据库（历史记录与本地账号表）以及系统级加密（`node:crypto`）的支持非常完善，适合以内容处理与团队权限管控为主的生产力工具。

## 2. 详细技术栈说明

### 2.1 前端展现层 (Frontend)
*   **框架**：**React 18 + TypeScript**。
*   **UI 组件库**：**Radix UI + Shadcn/ui**。考虑到现代、简洁的工具类设计风格，Shadcn/ui 的 `Switch`（账号启用/禁用开关）、`Dialog`（新增账号/重置密码弹窗）、`Table`（账号列表）与 `Tabs` 组件能提供极高的定制化自由度，非常符合设计稿要求。
*   **CSS 框架**：**Tailwind CSS**。用于快速实现响应式布局和浅色系现代风格。
*   **状态管理与路由守卫**：**Zustand**。
    *   管理跨页面的配置信息（如 API Key、本公司主营业务关键词、全局知识库状态）。
    *   管理**登录会话与角色权限状态 (`authSlice`)**：存储当前登录用户信息（`currentUser`）、角色（`admin` 管理员 / `member` 普通成员）与可用状态（`isActive`），控制未登录时强制渲染【登录页】，且仅在 `role === 'admin'` 时渲染左侧【账号管理】导航入口。

### 2.2 本地业务逻辑层 (Main Process / Local Backend)
*   **框架**：**Node.js** (运行在 Electron 主进程中)。
*   **本地数据库**：**SQLite (`better-sqlite3` + `sql.js` 双擎自适应)**。
    *   *用途*：持久化存储用户的“历史二创记录 (`history_records`)”、“本地知识库解析全文 (`knowledge_documents`)”以及“系统账号与权限表 (`users`)”，保证断网或重启后数据不丢失，且查询速度快。
    *   *ORM / 查询层*：支持使用 **Drizzle ORM** 或参数化预处理 SQL 语句，提供类型安全且防 SQL 注入的数据库操作。
*   **本地文件处理**：使用 `pdf-parse`（PDF 解析）、`mammoth`（Word `.docx` 解析）与原生 `fs`（`.txt` / `.md` 读取）在本地提取用户上传的知识库文件全文，避免将整个原始文件传到云端。

### 2.3 账号管理与可用性管控技术方案 (Account Management & Auth)

针对 PRD V1.2 新增的**「登录页」**与**「管理员控制账号是否可用（启用/禁用）」**需求，设计以下完整技术方案：

#### 1. 核心数据模型设计 (`users` 表结构)
在 SQLite 数据库中建立 `users` 表，通过 `is_active` 字段实现账号可用性的原子级控制：

| 字段名 | 类型 | 约束与默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| `id` | `TEXT` | `PRIMARY KEY` | 账号唯一标识（UUID） |
| `username` | `TEXT` | `UNIQUE NOT NULL` | 登录账号（工号/用户名/手机号） |
| `password_hash` | `TEXT` | `NOT NULL` | 经加盐哈希后的密码密文（严禁存明文） |
| `salt` | `TEXT` | `NOT NULL` | 每个账号独立的随机加密盐值 |
| `display_name` | `TEXT` | `NOT NULL` | 成员姓名或部门备注（如“张编导 - 内容组”） |
| `role` | `TEXT` | `NOT NULL DEFAULT 'member'` | 角色权限：`admin`（管理员）或 `member`（普通成员） |
| `is_active` | `INTEGER` | `NOT NULL DEFAULT 1` | **核心管控字段**：`1` 为可用（启用），`0` 为不可用（已禁用） |
| `created_at` | `TEXT` | `NOT NULL` | 账号创建时间（ISO 时间戳） |
| `last_login_at` | `TEXT` | `NULL` | 最近一次成功登录时间 |

#### 2. 密码加密与本地安全方案
*   **零外部编译依赖加密**：采用 Node.js 原生内置的 **`node:crypto`** 模块（使用 `crypto.scryptSync(password, salt, 64)` 加随机 16 字节 `salt`），无需额外安装易发生跨平台编译报错的 `bcrypt` C++ 扩展，即可实现工业级单向密码哈希校验。
*   **防误锁安全保护**：在主进程数据库层硬编码保护规则——系统内置超级管理员账号（`username = 'admin'`）及当前正在操作的管理员自身账号，禁止执行 `is_active = 0`（禁用）或 `DELETE` 操作，防止管理员误操作导致全员无法登录。

#### 3. 账号可用性 (`is_active`) 双层拦截机制
*   **第一层：登录入口拦截 (`auth:login`)**
    *   用户输入账号密码后，主进程先校验密码哈希；密码正确后立即判断 `user.is_active === 1`。
    *   若 `is_active === 0`，主进程直接返回 `{ success: false, errorCode: 'ACCOUNT_DISABLED', errorMessage: '当前账号已被管理员停用，无法登录系统' }`，前端登录页展示醒目告警并阻断进入工作台。
*   **第二层：核心业务 IPC 实时状态守卫 (`auth:verify-active`)**
    *   在触发耗时或消耗 API 额度的核心 IPC 操作（如 `video:parse` 提取视频、`llm:generate-stream` 生成二创脚本）前，主进程根据传入的 `currentUserId` 实时复核 `is_active` 状态。
    *   一旦管理员将某账号设为不可用，该账号不仅无法再次登录，正在运行的会话在触发二创操作时也会立即被主进程拦截并强制退回登录页。

#### 4. 部署模式选择：本地单机多账号 vs. 跨电脑云端集中管控
根据团队实际办公形态，账号管理支持平滑演进的两种部署模式：

| 部署模式 | 适用场景 | 技术实现栈 | 管控生效机制 |
| :--- | :--- | :--- | :--- |
| **模式 A：本地 SQLite 账号管控（默认内置，零服务器成本）** | 共用工作站、内网共享数据库目录、或本地权限验证与演示 | Electron 主进程 + 本地 SQLite `users` 表 + `node:crypto` | 管理员在【账号管理页】切换启用/禁用开关后，毫秒级写入本地 SQLite 数据库并即时生效 |
| **模式 B：轻量云端集中管控（多台电脑异地办公扩展）** | 团队成员各自使用独立电脑，管理员需远程实时关停某员工账号 | 国内直连 BaaS（**腾讯云开发 CloudBase** / **MemFire Cloud 国内版 Supabase**）或自建 **Node.js (Fastify) + MySQL/PostgreSQL + JWT** 极简鉴权服务 | 客户端登录与每次生成前请求云端 `/api/auth/status` 校验 `is_active` 状态；管理员在后台关闭某账号可用开关后，全网所有终端实时同步拦截 |

### 2.4 AI 与大模型集成层 (AI & LLM Integration)
*   **LLM 交互 SDK**：**OpenAI Node.js SDK**。
    *   支持 DeepSeek（`https://api.deepseek.com/v1`，国内直连首选）、通义千问、字节豆包、月之暗面 Kimi、OpenAI 等兼容接口无缝切换。
*   **RAG (检索增强生成 - 知识库与业务关键词注入)**：
    *   将本地提取的知识库全文（`fullContent`）、本公司主营业务概述（`companyBusinessProfile`）、分类业务关键词与左侧提取（或人工修改后）的热点文案拼接后发给大模型。
*   **流式输出 (Streaming)**：实现大模型 Server-Sent Events (SSE) 流式响应，让右侧二创界面实现“打字机”效果。

### 2.5 第三方服务接入 (3rd Party APIs)
*   **视频去水印与文案提取**：对接国内成熟的聚合 API（如聚合数据、十目 API 等），前端支持“仅提取文案（手动编辑后再二创）”与“一键提取并二创”两种调用模式。

## 3. 开发阶段规划建议
1.  **Phase 1 (MVP)**：完成 UI 界面（支持全自动一键二创与手动仅提取可编辑双模式），打通第三方解析 API 和大模型流式 API。
2.  **Phase 2**：引入 SQLite 本地数据库，完成历史二创记录的保存、多条件检索、读取展示与导出。
3.  **Phase 3**：完成本地知识库文件（`.pdf` / `.docx` / `.txt`）读取解析与本公司业务 Prompt 注入；完善多轮对话式迭代优化与版本回退功能。
4.  **Phase 4（账号鉴权与打包交付）**：在 SQLite 中新增 `users` 表与 `node:crypto` 加密鉴权服务，完成前置【登录页】与管理员专属【账号管理页（控制账号是否可用）】；使用 `electron-builder` 完成安装包构建与优化。
