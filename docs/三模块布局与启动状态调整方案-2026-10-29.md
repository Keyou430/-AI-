# 三模块布局与启动状态调整方案

- 日期：2026-10-29
- 范围：创作工作台、小红书图文二创、历史记录三个页面的渲染层调整，外加工作台启动状态的持久化调整。不改生成逻辑、IPC、主进程服务和数据库结构。
- 原方案依据：当时工作区源码。方案编写时未运行界面，第二、三节的高度和占比为估算；现已完成运行验收，实测数据见第十一节。
- 状态：已完成修改及源码／1.0.16 正式 ASAR 隔离验收；实测值、证据与边界见第十一节。
- 与旧文档的关系：`小红书图文二创页面布局优化方案-用户视角-2026-10-28.md` 描述的"左编辑、右预览"分页结构经用户确认继续沿用，旧文档整体保持有效。本文只在翻页条位置、左右栏栏头和底栏、空白展示区三处修订它，修订清单见第十节。旧文档第十二节记录的 1.0.15 验收证据，在本次改动后部分失效，需要重新验收。

## 一、需求

| 编号 | 模块 | 需求 |
|---|---|---|
| R1 | 创作工作台 | 重新打开软件时，素材区与脚本区一致，保持空白，不回显任何历史内容。链接输入框也清空 |
| R2 | 小红书图文二创 | 未粘贴链接时保留空白展示区，布局与工作台类似。用户确认采用"左编辑、右预览"，确认主按钮在左栏底部 |
| R3 | 小红书图文二创 | 保留"上一图／下一图"，但目前在右半区顶部，位置不合理。用户确认放在图片框正下方 |
| R4 | 历史记录 | 内容展示区过小。这里的"小"指内容区上方的标签页、标题和下方按钮占位太多，挤掉了可视高度 |
| R5 | 三个模块 | 内容展示区按相同思路扩大，至少过半，尽可能更大 |

关于 R3 的补充：用户要求"翻页条如果两个区域都需要，就延展至两个区域"。核对结果见 3.4 节，结论是只有右栏需要，不做横跨。

已确认的决定：

- 结构：左编辑、右预览。
- 确认主按钮：左栏底部。
- 翻页条：图片框正下方。
- 链接框：重启后清空。

## 二、现状核对

### 2.1 R1：素材区重启后回显的原因

- `src/store/useAppStore.ts` 的 `partialize`（约第 397 到 407 行）把 `linkInput`、`parsedVideo`、`editedTranscript`、`editedVisualSummary` 写进了本地存储。
- 脚本相关字段（`parsedScript`、`streamingScriptText`、`conversationMessages`、`refinementHistory`）没有写入，所以脚本区重启后为空。
- 工作台代码里没有读取 `historyRecords[0]` 的地方。素材区回显的是上一次提取或"重新编辑"留下的素材，它通常恰好等于最新一条历史记录。
- `merge` 的写法是 `{ ...current, ...stored }`。只在 `partialize` 里去掉字段不够，老用户已写入的旧数据首次启动时仍会被读回来。

### 2.2 R2、R3：图文页现状

- `src/views/ImageTextView.tsx` 已经是分页版：左栏是"文案／逐图／风格／素材／核对"五个分页，确认后改为"概览／发布文案／素材／核对"，右栏是图片预览。
- 没有草稿时，页面只显示一张居中的空状态卡片，没有左右两栏。
- 翻页条在 `ImageTextResult.tsx` 的右栏顶部，同一个固定栏头里还有状态行和"图片优化"按钮。
- `ImageTextPage`（`electron/services/imageTextTypes.ts` 第 36 到 46 行）只有 `text`、`visual`、`referenceIds`、`assetId` 等字段，没有原帖图序号。因此左栏的原帖素材不会随翻页变化。
- `App.tsx` 中没有图文草稿的启动载入逻辑，`useImageTextStore` 也没有 persist，所以图文页重启后本来就是空的。这一点只检查了 `App.tsx`，其他入口没有逐个查。

### 2.3 R4、R5：纵向占位估算

按 1366×768、侧栏展开估算。数字为"约"，没有实测。

| 位置 | 固定占位 | 内容区 | 主要来源 |
|---|---|---|---|
| 工作台 右栏（脚本） | 约 154px | 约 424px | 工具栏一行、分页标签一行、镜头翻页一行 |
| 图文页 左栏 | 约 340px | 约 270px，不到面板一半 | 三行栏头、分页标签、四行底栏 |
| 历史记录 右栏（脚本） | 约 230px | 约 435px | 标题、日期、操作按钮占两到三行，再叠标签和镜头翻页 |
| 历史记录 右栏（图文） | 约 235px | 约 430px | 同上，再加翻页条和状态行 |

内容区约占窗口 36% 到 45%。用户感觉的"约 1/4"比这个数字更低，可能是窗口更小，或 Windows 缩放比例大。需要用户提供窗口尺寸和缩放比例核对。

横向方面，三个页面右栏的网格比例都是 `1fr : 2fr`，右栏约占主区域 2/3，不是瓶颈。

## 三、调整方案

### 3.1 模块一：重启后保持空白（R1）

**做法**

- 在 `useAppStore.ts` 的 `partialize` 中去掉 `linkInput`、`parsedVideo`、`editedTranscript`、`editedVisualSummary`。
- 保留偏好类字段：`sidebarCollapsed`、`targetDurationSec`、`userCameraWork`、`keywords`、`settings`。
- persist 的 `version` 从 2 升到 3。`migrate` 中删除上述四个旧字段。
- `merge` 中显式忽略这四个字段，防止旧数据被读回。两处同时处理。

**行为变化**

- 没点生成就关闭软件，手填的素材会丢失。脚本区现在本来就是这样。已生成的脚本会自动存入历史，不受影响。
- "历史记录 → 重新编辑"仍把记录载入工作台，只是重启后不再回显。

**需要同步修改的测试**

`tests/devicePersistence.test.ts` 和 `scripts/desktopPersistenceSmoke.cjs` 很可能断言了素材被保留。这两个文件还没读过，实施时先读，再改成断言"素材和链接框不保留，设置和关键词保留"。

### 3.2 模块一：压缩纵向占位（R4、R5）

- `ScriptResult` 把工具栏、分页标签、镜头翻页合并为一行：左边是分镜、技巧、口播等标签，右边依次是镜头翻页（仅分镜和技巧页显示）、复制、优化脚本。右栏宽约 750px 可以放下，更窄时自动折成两行。
- 固定占位从约 154px 降到约 52px。
- 左栏底栏去掉"基于人工修改后的文案"那行提示，顶部右侧已有"已编辑"状态，约省 28px。
- `ScriptResult` 同时被历史记录使用，模块三会一起受益。

### 3.3 模块二：左编辑、右预览，空白展示区，压缩占位（R2、R4）

**结构决定（用户已确认）**：沿用 2026-10-28 文档已定、并已在 1.0.15 实现的"左编辑、右预览"，与工作台的"素材／脚本结果"同构。左栏的分页（确认前：文案／逐图／风格／素材／核对；确认后：概览／发布文案／素材／核对）、折叠块、`aria-label` 和测试依赖都不变，确认主按钮仍固定在左栏底部。本节只写相对旧文档新增或变化的部分。

**左栏压缩**（R4）

- 栏头从三行（标题、来源说明、第一条提示）压成一行：左边是标题，右边是"自动识别 · N 张"和"重新策划"（`ghost` 小按钮，从底栏移上来）。原帖标题已在"核对"分页的"原帖素材"里，不再占栏头。
- 第一条系统提示：有提示时才显示一行提示条，放在标签行下方；没有提示就不占位。多于一条时，其余仍收进"核对"分页的"还有 N 条提示"。
- 确认前的底栏压成两行，仍固定在左栏底部：
  - 第一行：`共 N 张 · 整套图片比例 [▾]`。
  - 第二行：主按钮"确认文案、张数及比例，开始生成 N 张图片"，占满宽度。
  - 比例来源说明、"确认前不会调用生图接口；确认后无需逐页确认"改为这两个控件的悬停提示（`title`），并用 `aria-describedby` 指向同样的文字供读屏使用；同时写进右栏未生成时的图片占位提示里。
- 确认后沿用旧文档：没有底栏，"概览"分页不变。

**右栏压缩**

- 栏头只保留一行：左边是"整套比例 3:4 · 已生成"这类状态文字，右边是"图片优化"（确认后才有）。原来的翻页行从栏头拆出，改放到图片框下方，见 3.4。
- 其余内容沿用：图片框、翻页条（新位置）、页面版本、"图内文字已核对"、本页报错、"本图文字与画面要求"折叠块。
- 右栏宽度不小于 760px 时，图片框与"本图文字与画面要求"可以并排，避免图片两侧留白；不够宽时上下叠放。

**空白展示区**（未粘贴链接，R2）：

- 始终渲染左右两栏，不再显示单张空卡片。
- 左栏：栏头标题"稿件与素材"，右侧小字"粘贴链接后显示"；标签行显示置灰的"文案／逐图／风格／素材／核对"；内容区一句引导：提取后，原帖标题、正文和图片文字显示在这里，核对并确认后开始生成。
- 左栏底栏在没有草稿时不显示，避免出现点不了的主按钮。
- 右栏：虚线图片占位框（默认 3:4）和一句引导，写法与脚本区的"脚本将在这里呈现"一致。
- 没有页面时不显示翻页条。
- 顶栏的链接输入保持可用，用户可以直接粘贴。

**与原需求 R2 的差异**：R2 原话是"右侧为配套文案＋图片区"。按用户确认的"左编辑、右预览"，配套文案（标题、正文、话题）的编辑仍在左栏"文案"分页，右栏只预览图片。如果希望右栏也显示文案，需要另行说明。

**与旧文档的关系**：本节没有拆掉左栏分页，旧文档的第五、六、十一节整体保持有效。需要同步修订的只有：翻页条位置（旧文档第六节线框、11.5）、左栏栏头和底栏（旧文档 11.5 的底栏三行）、右栏栏头（旧文档 11.5 的"翻页行和状态行"）。

### 3.4 模块二：上一图／下一图的位置（R3，用户已确认）

**确认的做法**：翻页条放在图片框正下方，只在右栏。

**核对结果**：`ImageTextPage` 没有原帖图序号字段（见 2.2 节），左栏不会随翻页变化原帖素材，所以翻页条不需要横跨两个区域。

**现状问题**：翻页条在右栏最顶部，与图片之间隔着状态行，用户看图、翻页的视线来回跳。

**调整后**：图片框正下方居中一行 `‹ 上一图 | 第 2 / 6 图 ▾ | 下一图 ›`。其下依次是页面版本、"图内文字已核对"、本页报错、"本图文字与画面要求"折叠块。

- 页数小于 2 时不显示翻页条。
- 第一张时"上一图"禁用，最后一张时"下一图"禁用。
- 按钮文字保持"上一图""下一图"，不改成纯图标。现有桌面脚本用 `clickText('下一图')` 按文字点击，并用 `select[aria-label=选择图片]` 切换。
- `aria-label="图片分页"` 和 `aria-label="选择图片"` 保留。
- 增加键盘 ←／→ 切换，焦点在输入框内时不响应。
- 图片未生成时翻页条同样可用，图片框里显示该页的图内文字预览。
- 左栏"逐图"分页仍读同一个 `activePageId`，行为与旧文档一致：翻页后同步显示该页的文字和画面；左栏在其他分页时，标签显示"逐图 · 第 N 图"。
- 翻页条移到图片下方后，必须保证它不被推出视口：右栏图片最大高度从 `50vh` 起调（现有为 `lg:max-h-[55vh]`），在 1366×768 下实测，要求翻页条底边在视口内。
- 历史记录的图文详情和窄屏"图片预览"视图用同一个组件，翻页条同样在图片下方。

### 3.5 模块三：历史记录压缩纵向占位（R4、R5）

**详情头改成一行**（`HistoryView.tsx` 约第 295 到 375 行）：

- 左边：标题，下面一行小字"日期 · 平台 · 时长或张数"。
- 右边：重新编辑、复制，以及把"导出文本""导出文档"合并为一个"导出"菜单（图文详情则是"复制发布文案""导出素材包"）。
- 高度从约 128px 降到约 60px。窄屏的"返回列表"按钮保留，放在同一行最左。

**脚本详情**：使用 3.2 节合并后的 `ScriptResult` 单行工具栏。历史里 `hideToolbar` 已经隐藏了脚本自带工具栏，所以只需让标签行和镜头翻页合并。

**图文详情**：与图文页右栏共用 `ImageTextResult`，栏头只留一行状态文字（历史里没有图片优化和版本切换，右侧为空），翻页条放在图片框正下方（见 3.4）。发布文案（标题、正文、话题）与图片在面板够宽时并排，窄时上下叠放。

**效果估算**：脚本详情固定占位从约 230px 降到约 112px，图文详情从约 235px 降到约 108px。

### 3.6 三个模块的内容区宽度（R5）

横向不是主要瓶颈（见 2.3 节），只做小幅调整：

- 三个页面外层间距 `p-5 gap-5` 收到 `p-4 gap-4`，约多出 16px 宽。
- 历史记录：左栏改为 `clamp(260px, 22%, 320px)`，右栏占满剩余，纯列表不需要更宽。
- 工作台和图文页：左栏改为 `clamp(300px, 30%, 440px)`。这两个页面的左栏都有文本内容，300px 是可用下限，不再往下压。
- 把这三种列宽写成公共的常量或类，避免三处各写一遍。
- 图文详情在面板够宽时用图片和文案并排，避免图片两侧留白。

### 3.7 估算后的内容区占比

滚动内容区高度占所在面板高度。下表用 2.3 节的估算像素值重新计算（面板高度＝固定占位＋内容区），仍是估算，验收时以实测为准。

| 面板（1366×768） | 面板高度 | 固定占位 现在 → 改后 | 内容区占比 现在 → 改后 |
|---|---|---|---|
| 工作台 右栏（脚本） | 约 578px | 约 154px → 约 52px | 约 73% → 约 91% |
| 图文页 左栏（确认前，含底栏） | 约 610px | 约 340px → 约 188px | 约 44% → 约 69% |
| 历史记录 右栏（脚本） | 约 665px | 约 230px → 约 112px | 约 65% → 约 83% |

图文页左栏改后占位约 188px：栏头一行约 44px、标签行约 44px、两行底栏约 100px。因为确认按钮按用户决定留在左栏底部，这一块比"无底栏"的方案低。确认后没有底栏，内容区占比约 85%。

宽度方向：历史记录右栏占窗口宽度约 53% → 约 58%（1366）、约 59%（1440）、约 64%（1920）。

## 五、测试适配

现有桌面脚本依赖下列页面元素，改动时保持不变：

| 依赖 | 说明 |
|---|---|
| `[aria-label=图文策划与确认]` | 保留在左栏整个编辑区上，不改名 |
| `[aria-label=图文结果]` | 保留在右栏面板上 |
| `select[aria-label=选择图片]`、`select[aria-label=页面版本]` | 保留；翻页条移位后仍在 `[aria-label=图文结果]` 内 |

## 八、风险

- **工具栏合并后窄窗口会折行。** 折行后占位回到现在的水平，但窄屏本来就是单栏切换。
- **翻页条移到图片下方后可能被推出视口。** 右栏图片最大高度要下调并实测，否则小窗口下翻页条需要滚动才能看到，比现在更差。
- **悬停提示触屏看不到。** 比例来源和"确认前不调用生图接口"改为悬停提示后，触屏和键盘用户看不到，所以要同时写进图片占位提示和 `aria-describedby`。
- **与 R2 原话有出入。** R2 原话是右侧放配套文案加图片，采用"左编辑、右预览"后，文案编辑仍在左栏。已在 3.3 节注明。
- **已验收的布局被再次修改。** 旧文档第十二节记录了 1.0.15 的布局验收和截图，本次改动会使其中涉及栏头、底栏、翻页条的截图失效，改完需要重跑 `smoke:desktop`、回归脚本并更新证据。
- **图文页改动量比之前设想的小。** 分页结构不动，只改栏头、底栏、右栏顺序和空白状态，可以与历史记录的详情头压缩分开提交。
- **持久化版本升级不可逆。** 旧版本客户端不会读到 v3 数据的差异，但本地存储里被清掉的素材无法找回。只影响工作台未生成的草稿，影响面小。
- **回滚。** 除 R1 外都只涉及渲染层，撤销相关提交即可。
