# 员工版安全审查

> 历史架构报告：1.0.3 已按最新需求改为单一通用包，服务器仅作账号鉴权，API Key 加密保存在本机并直连供应商。下文服务端业务代理和公司密钥托管属于旧版设计；当前行为及安全边界以 README.md 和集中授权部署.md 为准。


> 修复状态：下方四项为 1.0.0 审查记录，1.0.1 已完成对应修复并部署。修复验证和保留限制见文末。

审查日期：2026-10-22。审查对象：员工版 1.0.0、对应源码及当前 Ubuntu 授权服务。结论：已复现 4 项安全问题，其中 3 项应优先处理；当前版本不适合作为能够抵御员工主动篡改的强授权系统。

本轮只审查并记录，没有修改业务代码、部署配置或原安装包。线上仅做状态、配置、文件权限、代码哈希及健康检查；异常登录、包篡改、密钥持久化和停权期间的流式任务均在本机隔离环境验证。

## 发现概览

| 优先级 | 问题 | 验证结果 |
| --- | --- | --- |
| P1 | 员工包可修改配置切换为本机授权，绕过服务器停权 | 临时副本实测通过，无服务端账号即可初始化本机管理员并调用业务 IPC |
| P1 | 登录限流混淆代理后的客户端，可阻断其他客户端登录 | 隔离服务实测，另一来源携正确密码仍收到 429；更换用户名不触发同 IP 总量限制 |
| P1（使用公司密钥时） | 模型和解析 API Key 明文持久化，账号失效后保留 | 使用占位密钥实测，两个 Key 均直接出现在持久化 JSON，授权失效后仍在 |
| P2 | 停权不会取消已开始的生成任务 | remote 模式隔离实测，授权拒绝后仍发送 148 个片段，最终报告成功 |

P1 表示建议在扩大员工分发前优先处理；P2 表示授权撤销链路存在需要修复的缺口。没有证据表明上述问题使普通成员直接获得服务器管理员权限。

## 1. 员工包可绕过服务器授权（P1）

位置：[desktopAuth.ts](D:/骏冠/新媒体/video-remix-ai-assistant-full/electron/services/desktopAuth.ts:8) 读取包内 authMode，第 15 行允许切换到 AuthService 本机模式；[package.json](D:/骏冠/新媒体/video-remix-ai-assistant-full/package.json:1) 的打包配置同时保留两种实现。

根因：员工版和普通版共用可切换的授权实现，授权模式由本机可写的 package.json 决定。实际员工可执行文件的 EnableEmbeddedAsarIntegrityValidation、OnlyLoadAppFromAsar 均为关闭，RunAsNode、NodeOptions 和 Inspect 参数支持为开启；安装包签名状态为 NotSigned。

复现：只对临时目录中的员工 app.asar 副本等长修改 authMode，不修改业务 JS；通过同版本 Electron 加载副本。getAuthStatus 返回 local/needsSetup=true，setupAdmin 成功，历史读取和账号列表 IPC 均成功。全程没有使用服务端账号，也没有修改原交付文件。

影响：具备本机文件修改能力的员工，可绕过远程授权继续使用本地功能；管理员停用该员工的服务器账号不能阻止这种副本运行。此处获得的是本机管理员，不是服务器管理员。

建议：员工版发布产物移除本机模式及初始化管理员入口，启用 ASAR 完整性和相关加载限制、关闭不需要的调试入口，并签名发布。上述措施可以提高篡改成本，无法从根本上约束员工完全控制的电脑；需要严格控制的模型调用、解析调用和额度应在服务器执行并逐次鉴权。

## 2. 登录限流可被用于阻断其他客户端（P1）

位置：[authServer.ts](D:/骏冠/新媒体/video-remix-ai-assistant-full/server/authServer.ts:75)、[authService.ts](D:/骏冠/新媒体/video-remix-ai-assistant-full/electron/services/authService.ts:61)。实际 Caddy reverse_proxy 指向 127.0.0.1:3080。

根因：登录限流键使用 socket.remoteAddress 与用户名，经过 Caddy 后服务端看到的来源为代理连接地址。达到默认 10 次失败后，在约 15 分钟窗口内会先返回 429，连正确密码也无法校验。限流用户名转为小写，而账号查询区分大小写，两种写法还会共享同一计数。另一方面，没有独立的每来源总体登录预算，更换用户名仍会继续执行同步 scrypt 运算。

复现：隔离服务将阈值缩为 2，两次错误登录后，使用另一 X-Forwarded-For 来源和正确 admin 密码仍收到 429；随后同一连接来源轮换 5 个用户名，均继续进入密码验证并返回 401，没有触发总量限流。线上未执行此测试。生产默认阈值 10 和 15 分钟窗口来自实际运行代码；服务器编译文件哈希已与本地核对一致。

影响：攻击者可以阻断管理员或员工的正常登录。轮换用户名还可持续消耗同步密码计算资源；由于客户端依赖授权服务并在网络超时后锁定，这会影响服务可用性。本轮未进行高并发压测，未声称已造成全员掉线。

建议：仅在可信回环代理来源下读取并验证客户端地址，分别限制每 IP 总量和账号尝试，并使用户名规范化与账号查询一致；密码校验改用异步 scrypt 并限制并发。不能无条件信任外部提交的 X-Forwarded-For，也应避免攻击者轻易将一个账号在所有来源上锁死。

## 3. 第三方 API Key 明文落盘，停权不撤销（P1，取决于密钥用途）

位置：[useAppStore.ts](D:/骏冠/新媒体/video-remix-ai-assistant-full/src/store/useAppStore.ts:399)、[持久化配置](D:/骏冠/新媒体/video-remix-ai-assistant-full/src/store/useAppStore.ts:416)、[useAuthStore.ts](D:/骏冠/新媒体/video-remix-ai-assistant-full/src/store/useAuthStore.ts:49)。

根因：settings 包含 llmApiKey 和 videoParserApiKey，整个对象经 Zustand persist 写入 localStorage；退出和授权失效仅清空登录用户，没有清除密钥。模型和解析请求由客户端直接携带这些 Key 调用供应商。

复现：在隔离存储中通过实际 updateSettings 写入两条占位密钥，持久化 JSON 中能直接取回原值；调用 invalidate 后原值仍保留。没有读取、输出真实业务密钥。

影响：如果员工端配置公司共用 Key，员工可以复制后脱离本程序调用供应商，停用软件账号不能撤销供应商 Key。属于该 Windows 用户本机访问能力的风险，不代表互联网用户无需条件就能读取；若员工使用自己的 Key，公司的风险相应较低。

建议：公司共用 Key 放在服务端，员工经带账号鉴权和额度约束的接口调用。必须保留本地 Key 时，至少移出 renderer/localStorage，改由主进程使用系统安全存储；但本机加密不能保证对持有同一 Windows 用户权限的员工保密，也不能替代服务器端授权。

## 4. 授权失效后在途生成仍继续（P2）

位置：[main.ts](D:/骏冠/新媒体/video-remix-ai-assistant-full/electron/main.ts:173)、[llmService.ts](D:/骏冠/新媒体/video-remix-ai-assistant-full/electron/services/llmService.ts:173)。

根因：业务 IPC 仅在进入时校验授权；授权监控触发锁定后，没有取消关联的生成请求，流式回调仍持续发送片段，完成时也没有检查会话是否已变更。退出登录存在相同的取消缺口。

复现：保留正式包全部业务 JS，仅在临时副本把授权地址指向隔离 HTTPS 服务，使用 remote 模式登录成员并开始仿真流式生成。管理员停用该成员后 verifyActive 已失败，但后续仍收到 148 个片段，原生成请求最终返回 success=true。仅使用仿真输出，没有产生商业模型费用；不把这一结果表述成已验证供应商端计费行为。

影响：已经开始的任务可以在停权或退出之后继续完成。新的业务请求仍会被拒绝，本问题不等于停权后可以持续新建任务。实际模型流也没有授权关联的取消信号，存在继续请求和输出的代码路径。

建议：将任务绑定到窗口会话及其版本，失效、退出或窗口关闭时中止对应 AbortController；停止向失效会话发送片段和成功事件，并在完成写回前再次验证会话归属。已提交给供应商的内容无法通过取消请求收回。

## 已确认的有效保护

- 9 项 remoteAuth 测试通过：普通成员不能管理服务器账号，停用及密码重置撤销全部服务端会话，重新启用不恢复旧会话，配置缺失拒绝启动，正常客户端离线锁定。
- HTTPS 健康检查正常，授权后台只监听 127.0.0.1:3080，公网由 Caddy 443 代理。
- 运行用户为 remixauth，数据库及日志目录隔离；数据目录权限 0700，数据库 0600，初始管理员密码文件 root:remixauth 0640。
- 服务端密码使用 scrypt 加盐哈希；随机会话令牌仅在服务端保存摘要，员工端会话令牌在主进程内存中。
- 包文件列表未发现 PEM、KEY、管理员初始凭据文件或 SQLite 数据库。这不是对所有二进制内容的全面凭据扫描。
