# 核心问题优化与安全加固记录 (2026-10-29)

针对审查中发现的 3 项高优先级隐患（第 1、2、4 项），已在源码中完成修复并补充针对性回归测试。

---

## 一、修改清单与变更详情

### 1. 知识库 Token 膨胀与多轮对话历史优化（优化项 1）
- **问题隐患**：原实现将所有启用本地知识库文档全文（`fullContent`）无条件原样拼接入提示词，且多轮优化时的历史对话列表无截断机制，导致单次模型调用的 Token 消耗巨大、费用陡增，甚至极易触发模型上下文超限报错。
- **改动文件**：
  - 新建 `src/lib/knowledgeContext.ts`：
    - 设立 `KNOWLEDGE_CONTEXT_CHAR_BUDGET = 12000`（约 1.2 万字符预算上限）。
    - 启用文档总字数未超限时保留原样完整注入；超限时切分段落片段，结合核心业务词（权重 5）、行业转化词（权重 3）、原帖标签（权重 2）及素材正文二元组进行相关度排序，动态节选得分最高的核心段落，并在提示词中注明节选说明。
  - 修改 `src/lib/promptBuilder.ts`：
    - 接入 `buildKnowledgeContext`，在构建 `userPrompt` 时注入预算控制后的知识库上下文。
  - 修改 `electron/services/llmService.ts`：
    - 新增 `limitConversationHistory` 工具函数，多轮历史最多保留最近 6 条消息（约 3 轮问答），总字符数限制在 20,000 以内；旧轮次的用户提示词自动截除冗余的素材与知识库全文，仅保留任务开篇与修改指令，从根源遏制 Token 累加。

### 2. 模型配置统一安全管理与权限收敛（优化项 2）
- **问题隐患**：主进程中的测试连接与脚本流式生成接口回退使用了渲染进程传入的配置；`llmService.ts` 还保留了 `process.env.LLM_API_KEY` 及写死的默认模型，存在绕过本地安全存储与 HTTPS 校验、私自更改请求目标的风险。
- **改动文件**：
  - 修改 `electron/services/llmService.ts`：
    - 移除环境变量密钥兜底和硬编码端点，新增 `requireConfig` 校验，缺失任意一项直接抛出明确的“前往系统设置配置”中文提示。
  - 修改 `electron/main.ts`：
    - 增加 `storedLlmConfig()` 辅助函数，`llm:test-connection` 与 `llm:generate-stream` 强制仅使用操作系统加密存储中的本地供应商配置，忽略前端 IPC 传入的明文 `config`。
  - 修改 `src/services/ipcClient.ts`：
    - 前端测试连接与生成请求不再在 IPC 载荷中传输密钥副本。

### 3. WASM 备用数据库（sql.js）原子落盘防损坏（优化项 4）
- **问题隐患**：在缺少 C++ 编译环境的 Windows 设备上切换至 `sqlite3-wasm` 引擎时，每次数据变动直接通过 `fs.writeFileSync` 整体覆盖目标 `.sqlite` 文件。若在落盘中途遭遇断电、杀毒软件锁文件或程序崩溃，数据库文件会因截断而永久损坏。
- **改动文件**：
  - 修改 `electron/db/sqliteService.ts`：
    - 新增 `writeFileAtomicSync(target, data)`：先将数据写入带有进程 PID 的同目录临时文件（`.tmp`），调用 `fs.fsyncSync` 强制物理刷盘，随后通过 `fs.renameSync` 原子性替换目标文件。
    - 增加 Windows 常见文件占用错误（`EPERM`, `EBUSY`, `EACCES`）退避重试机制（最多重试 5 次），绝不降级为直接覆写。
    - 在 WASM 数据库加载时增加 `removeStaleTemporaryFiles` 清理上次异常终止留下的垃圾文件。

## 二、专项自动化测试与验证

新增专项测试用例集 `tests/optimizationFixes.test.ts`，共 5 项独立测试：
1. `知识库未超预算时完整注入，超预算时按业务关键词与相关度节选`：验证未启用文档排除、预算截断有效性及相关度命中。
2. `splitIntoChunks 段落切片按目标长度合理拆分`：验证超长文本分块算法。
3. `多轮历史限制保留最近轮次并压缩旧的用户提示词`：验证超长对话截断与旧提示词压缩。
4. `llmService 拒绝不完整或空的接口配置`：验证防御未配置或前端伪造配置。
5. `writeFileAtomicSync 安全覆盖原文件并确保原子落盘`：验证临时文件落盘、强制刷盘及原子替换过程，确认无临时文件残留。
