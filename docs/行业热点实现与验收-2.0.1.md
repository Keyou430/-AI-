# 行业热点实现与验收（2.0.1）

更新日期：2026-11-10。

## 当前实现

- 数据源采用 UApi 聚合热榜，覆盖抖音、小红书、微博、知乎。仅请求平台类型，不向热榜数据源提交知识库、关键词、模型密钥或创作内容。
- 已移除内置热点标题、虚构热度和用当前时间包装旧选题的逻辑。记录数据源更新时间与本机获取时间，超过 24 小时标为过期；行业推荐排除过期及刷新失败的数据。
- 本机缓存有效期 20 分钟；手动刷新绕过缓存。请求失败时保留上一次成功结果与原时间，明确标注状态；首次失败显示不可用。
- 行业画像优先使用已配置的文本模型；失败时使用规则。模型输入最多取前 5 份启用文档的摘要，每份最多 400 字符，以及最多 30 个非禁止业务词。禁止词用于过滤话题。
- 无资料时可先浏览热榜，也可选择行业预设。手动行业和标签在本设备保存；自动画像根据实际输入摘要和关键词变化更新。
- 热点先按行业规则排序，再对前 15 条候选进行 AI 精排。界面区分规则匹配分与 AI 匹配分，分数用于选题排序。
- 视频入口预填话题背景，用户在工作台点击生成。图文入口调用文本模型生成策划草案，用户确认文案、张数、比例后才提交生图。
- 覆盖未保存稿件前确认；图文提供保存后转入。目标任务运行时拒绝覆盖。取消确认保留现有稿件。
- 来源快照包含真实平台、标题、链接、数据源、原更新时间及采用的切入角度，复用现有历史 JSON 保存。旧历史继续兼容，无新增表或数据库迁移。
- 热榜获取与模型分析沿用现有鉴权任务控制；退出或授权失效后的旧响应不会恢复列表。

## 数据源验证

2026-11-10 在本机执行只读验证：微博直连接口返回 HTTP 403；知乎直连接口返回 HTTP 401；抖音直连接口返回 HTTP 200 空内容。

UApi 四个平台请求均返回 HTTP 200 和有效结构：抖音 50 条、微博 50 条、知乎 30 条，更新时间为当日；小红书 20 条，更新时间为 2026-10-27，属于过期数据，不能按实时榜单展示。该结果是一次网络验证，不代表持续可用性承诺。产品界面始终展示实际来源时间。

## 操作方式

1. 点击左侧“行业热点”，选择行业预设，或在设置中启用知识库并添加业务关键词。
2. 通过平台、搜索、仅看高契合筛选话题；先查看来源和更新时间。
3. “转视频二创”后核对背景与拍摄要求，再点击生成脚本。
4. “转图文策划”后核对草案，再确认文案、张数与比例，启动图片生成。
5. 从“历史记录”按真实来源平台查找已生成内容，来源信息随记录保留。
